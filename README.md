## 它和别的「AI 写周报」有什么不一样

市面上的工具都在做**加法**——把你手打的三行字扩成八百字。

这个做的是相反的事：**把二十件杂事压成三件说得清的事**，每条带一个能被验证的数字，并明确标出这条要你领导做什么。

因为汇报被扫一眼就过的原因，从来不是写得不够长。

|  | 常见工具 | 本工具 |
|---|---|---|
| 方向 | 扩写、润色 | **压缩、前置、去修辞** |
| 数字 | 留下 `XX%` 让你自己填 | 要求你补，补不出标 `[待填]`，**绝不代填** |
| 留存 | 每次从头开始 | 一次交付顺手沉淀本地素材库，日报素材可复用到年终述职 |
| 坏消息 | 不处理 | 有专门模块：时机判断、归因红线、可转发版本 |
| 交付后 | 结束 | 预测对方可能怎么回，你分别怎么接 |

## 主要能力

### 📉 做减法，不做加法

你给二十件事，它交付三到五件，并告诉你砍掉的理由。被砍的不丢，进素材库。

### 🔢 可验证锚点校验

扫描所有成果描述，形容词一律要求换成数字。

```
❌ 显著提升了响应速度
✅ 接口响应从 800ms 降到 200ms

❌ 大幅优化了流程
✅ 审批环节从 7 步减到 3 步，平均耗时从 2 天到 4 小时
```

### 🎯 动作项标注

每条汇报都标注它要领导做什么——**知悉 / 决策 / 支援 / 无需动作**。

如果一份周报里全是「知悉」，它会提醒你：这意味着这周你没有推动任何需要上级参与的事。

### 📁 长期素材沉淀

每次交付可选沉淀一份本地《工作留档》，存的不是成品副本，是**减法之前的原始事实**——包括那些没写进周报的小事。

> 今天不值一提的「帮隔壁组梳理了数据口径」，明年述职时可能是「跨部门影响力」那一栏唯一的证据。

### ⚠️ 坏消息汇报

市面上的工具只会帮你报喜。但职场里最难写的那份汇报，永远是项目延期了、目标没达成、你搞砸了一件事。

- **时机判断优先于措辞**——坏消息最大的错误不是写得难听，是报晚了
- **必须三件套**——发生了什么 / 影响面 / 我的方案（至少两个选项）
- **归因红线**——不点名甩锅，也不过度自责
- **可转发版本**——你领导也要向他上级交代，替他备好这层

### 🎭 模拟评审

让 AI 扮演你的直属领导或答辩评委，按固定维度打分并迭代（上限 2 轮，防止把你自己的语气磨掉）。

评审角色会具体到「技术出身还是业务出身」「看数字还是看风险」——抽象的「上级」给不出有用的反馈。

### 🏛 按考核体系适配

述职材料按你所在环境的话语体系组织，而不是一套模板套所有人：

- 互联网大厂：impact story、量化影响、scope 分级、360 视角
- 体制内 / 事业单位：德、能、勤、绩、廉五段，突出德与绩
- 说不清的：通用结构，不追问

## 三条它不会做的事

这些是写死的红线，任何情况下不突破：

1. **绝不虚构数字、日期、人名。** 你没给的写 `[待填]`，不给你编一个「看起来合理」的数
2. **不淡化坏消息。** 禁止用「进度略有滞后」描述延期一个月
3. **不替你注水。** 这周确实没干什么，就不帮你编——它会去挖你自己没意识到的产出，挖不出就如实写最短的版本

> 汇报是要被验证的。编造的数字被抓到一次，损失的不是这一条周报。

## 安装

### 一行命令（自动识别 runtime）

```bash
npx skills-cli install bys-work-report
```

### 手动安装

克隆本仓库，把 `bys-work-report/` 整个目录放进你所用工具的 skills 目录：

| Runtime | 路径 |
|---|---|
| Claude Code | `~/.claude/skills/` |
| Cowork | 设置 → Skills → 导入 |
| Codex | `~/.codex/skills/` |
| Cursor | `.cursor/skills/` |
| 其他兼容 runtime | 参照该工具的 skills 目录约定 |

### 作为参考资料使用

不安装也可以——把 `SKILL.md` 和 `references/` 里的内容直接贴给任何 AI 助手，同样有效。

## 用法

装好之后，直接说人话就行：

```
帮我写个周报
```
```
这周的日报
```
```
年底要述职了，帮我准备材料
```
```
项目要延期了，怎么跟领导说
```
```
把这段整理成月度汇报
```

想走完整引导（建立个人档案和素材库）：

```
初始化 工作汇报助手
```

**不初始化也能直接用。** 第一次使用会立刻干活，交付完才问你要不要留档——先给价值，再要投入。

## 你的数据在哪

全部在本地。

- `工作留档.md` —— 你的素材库
- `我的汇报档案.md` —— 你的行业、领导风格、考核体系

两个文件都在你自己选定的文件夹里，可查看、可编辑、可备份、可随时删除。**不上传、不外发。**

涉及公司内部信息时不做联网检索；任何联网操作都会先征得你同意，并说明要查什么。

## 常见问题

**我们公司有固定的周报模板，能用吗？**
可以。把空模板或你上次写的那份发给它，它会按你们的字段结构填。复杂的合并单元格 Excel 它会明说填不了——明确说做不到，好过勉强填错。

**它会模仿我的语气吗？**
会学你们公司的黑话、格式惯例、详略程度，但**不学写作水平**。因为你过去写得不够专业是很可能的，照着学就是把问题一起学过来。

**为什么不给我把数字填上？**
因为汇报会被验证。它宁可让你带着 `[待填]` 去查一分钟，也不给你一个可能让你在追问时下不来台的数字。

**述职 PPT 会做吗？**
会，而且配逐页口述稿——述职是当场讲的，PPT 只是提词器。页数和口述稿字数按你的答辩时长倒推。
