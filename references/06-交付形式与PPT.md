# 交付形式与 PPT 规范

---

## 一、给默认值 + 一句话兜底

**不要弹四选一让用户挑。** 按 Mode 给默认，做完顺带说一句允许改。

| Mode | 默认交付 |
|---|---|
| M1 日报 / M2 周报 | 可直接粘贴进 IM 的纯文本 |
| M3 月报 / 项目汇报 | 文档（.md 或 .docx） |
| M4 述职 / 晋升答辩 | PPT + 逐页口述稿 |
| M5 年终总结 | 文档，问一句要不要 PPT |
| M6 坏消息 | 视紧急度：紧急→IM 短文本 + 可转发版；不紧急→邮件格式 |

说法示例：

> 「这种一般直接发消息就行，我按聊天格式给你了。需要正式文档或者 PPT 的话说一声。」

### 各形式的格式要点

**IM 纯文本**：不要用 Markdown 标题符号（粘过去是乱码）。用序号、短横线、空行分隔。总长度控制在手机一屏内。

**邮件**：主题行要带结论（"支付模块上线时间调整至 8/29"，不是"关于支付模块的汇报"）。正文首段即结论。

**文档**：开头必须有 5 行以内的结论摘要，让领导只读这段也能做决策。

## 二、公司固定模板回填

**默认假设用户没有模板。** 初始化时问一次并存档，之后不再问。答"没有"就永不打扰。

### 2.1 主入口的问法

比"上传空模板"更好用的是：

> 「把你上次写的那份周报发我看看？」

一份填过的历史周报同时给了三样东西：字段结构、公司黑话、以及格式惯例。

（注意：**只学环境不学文笔**，见 references/02 第六节。）

### 2.2 Word 模板

- 解析文档结构，识别字段与占位
- **保格式回填**，不重新排版
- 表格型模板保持行列结构
- 有页眉页脚、编号、签批栏的，全部保留

### 2.3 Excel 模板

- 能解析的规整表格 → 按列回填
- 遇到复杂合并单元格、多 sheet 交叉引用、宏 → **老实说做不了**：

  > 「你这个表结构有点复杂，我怕填错位。内容我按你们的字段整理好了，你复制粘贴一下更稳。」

**明确说做不到，远好于勉强填错。填错一次用户就再也不信了。**

## 三、PPT 规范（主要用于 M4）

### 3.1 核心判断

**述职 PPT 的评判标准不是好看，是能不能被讲。**

它是口述时的视觉支架，不是阅读材料。所有规范都从这一条推出来。

### 3.2 硬规范

1. **一页一个论点**
2. **论点写进标题**
   - ❌ 「XX 项目进展」
   - ✅ 「XX 项目提前两周交付，节省 30 人日」
3. **每页至少一个可验证数字**
4. **正文控字数**，禁止整段文字。正文是提示，不是稿子
5. **结构按能力维度 / 影响半径组织**，不按时间顺序
6. **按时长倒推页数**（见 references/03 第 2.1 节）
7. **必配逐页口述稿**

### 3.3 逐页口述稿

每页配：

- 这一页要讲的话（口语，不是书面语，200–250 字/分钟折算）
- 这一页的时间预算
- 可能被打断追问的点

口述稿要能直接念。写完自检：**念一遍，有没有哪句话正常人不会这么说？**

### 3.4 风格选择：开始前先选，用人话，给推荐值

🔴 **检查点 C4：用户选定风格前，禁止开始生成 PPT。** 做完再改风格是最大的返工。

也不要用 `dusk-violet-consulting` 这种用户看不懂的名字。按行业先给推荐值：

| 风格 | 适合 | 特征 |
|---|---|---|
| **稳重克制** | 银行、国企、事业单位、传统行业、向高层汇报 | 深蓝/深灰主色，克制留白，无装饰元素，正文衬线或黑体 |
| **数据驱动** | 互联网、咨询、金融分析、技术岗 | 图表占主体，单一强调色，大量数字，高信息密度 |
| **简洁现代** | 创业公司、产品/设计/市场岗 | 大留白，一个亮色，无衬线字体，弱化边框 |

问法：

> 「你是互联网技术岗，我默认用『数据驱动』这套——图表为主，一个强调色。想换成更克制的商务风也可以，说一声。」

**目的是避免所有人做出来的 PPT 都一模一样，也避免做完返工。**

### 3.5 通用设计要点

- 字号层级最多三级：标题 / 正文 / 注释
- 一页最多一个强调色，其余用中性灰阶
- 留白不小于 12%，四周边距一致
- 图表优先于文字，文字优先于图片
- 页码必须有（答辩问答时评委会说"回到第 7 页"）

## 四、生图的边界

**默认用图表，不用生图。**

理由不是审美偏好，是从信号理论推出来的：**AI 味的插图会让评委怀疑内容也是 AI 写的，这直接摧毁信号可信度。** 述职最怕这个。

述职里真正加分的视觉是数据可视化：趋势线、前后对比、漏斗、占比。那需要的是 Chart，不是生图模型。

**生图只用于两处：**

1. 封面 / 章节页的抽象背景（纯装饰，零风险）
2. 用户明确要求时

检测到环境中有生图能力时，可以提一句「要不要给封面配张图」，但**不主动往内容页塞**。

## 五、交付动作

1. 用当前 runtime 的文件交付方式给文件（Cowork 下是 `mcp__cowork__present_files`），不要把全文糊在聊天里。工具不可用则给绝对路径，再不行就贴正文——**交付内容优先于交付形式**
2. 简短说明改了什么、为什么这么组织，不要长篇解释
3. 附预测的对方回复（见 references/05）
4. 问留档
