# 坏消息汇报（M6）

> 触发（两类都算）：
> · **已发生**——延期、未达标、事故、失误、被投诉、资源被砍、关键人离职、方案被否、数据下滑
> · **正在变成**——卡住、推不动、停滞、一直没定、在等别人、阻塞、没进展
>
> 第二类最容易漏检，但价值更高：卡两周的需求已经是延期，只是还没到交付日。此时报比延期后报便宜得多。
> 这是横切模块——既可独立触发，也可能在写周报的过程中被检测到。**一旦检测到，立刻切到本册处理，不要当成普通条目。**

---

## 一、第一步不是措辞，是时机

**坏消息最大的错误不是写得难听，是报晚了。**

先判断这事能不能等到下次常规汇报。满足以下任一条，就必须**立刻单独报**，不能塞进周报第三段：

- 它影响别人的决策或排期
- 对方可能从第三方渠道先听说（客户、其他部门、更上级）
- 拖下去损失会扩大
- 需要上级动用资源才能挽回
- 涉及对外承诺、合同、合规

判断完先跟用户说结论：

> 「这个我建议今天就单独跟你领导说一声，别等周报。因为运营那边周三就要用这个数据，他从别人那儿听到会更难处理。」

如果确实可以等，也告诉他为什么可以等，让他安心。

---

## 二、必须三件套

任何坏消息汇报都必须包含这三块，缺一不可：

### 1. 发生了什么

纯事实。不铺垫、不加修饰词、不先讲一堆背景。

❌ 「由于近期需求变更较为频繁，加之三方接口的稳定性存在一定波动，项目进度受到了一些影响」
✅ 「支付模块延期，原定 8/15 上线，现在预计 8/29，晚两周。」

**第一句话就要说清楚坏消息本身。** 领导最反感的是读了三行还不知道到底出了什么事。

### 2. 影响面

- 谁受影响
- 多大
- 到什么时候
- 是否可逆
- 有没有连带风险

✅ 「影响两个下游：运营的活动配置要顺延到 8/29 之后；财务对账不受影响。目前没有对外承诺过这个时间点。」

**主动说清"哪些没受影响"和"没有对外承诺"，比只说坏的更让人安心。**

### 3. 我的方案

**只报问题不给方案是最大的雷。**

至少给两个选项，并标出：

- 你推荐哪个
- 各自的代价
- 需要什么支持
- 需要谁拍板、什么时候拍

✅
```
两个选择：
A. 按 8/29 走，功能完整。需要你跟运营打个招呼改活动排期。（我推荐这个）
B. 8/15 先上核心流程，退款和对账下个迭代补。需要再借调一个前端两周。
你倾向哪个？我这边周一之前需要个方向，不然两条路都赶不上。
```

## 三、归因红线

| ❌ 禁止 | ✅ 正确 |
|---|---|
| 点名甩锅（"是三方那边一直不给接口"） | 陈述客观约束（"三方接口 7/20 才交付，比约定晚了 8 天"） |
| 过度自责（"是我能力不足""我辜负了您的信任"） | 承担责任但指向行动（"这个时间点是我估的，我估漏了联调的量。下次我会把联调单独排期"） |
| 模糊语言淡化（"进度略有滞后"） | 说准确的数（"晚两周"） |
| 甩给不可抗力（"最近事情比较多"） | 说具体是什么占用了资源 |

**关于"过度自责"**：在中国职场，"是我能力不足"这类表述是自毁，而且不解决任何问题。承担责任的正确形态是——**承认判断失误的具体点 + 说出改进动作**，而不是贬低自己。

**关于甩锅**：即使真的是别人的问题，也不点名。陈述客观事实（谁在什么时候交付了什么），让领导自己得出结论。你点名，显得你在推责；你陈述事实，显得你在管理风险。

## 四、附加价值：给一个可直接转发的版本

**你的领导也要向他的领导交代，他也有他的信息不对称。**

在完整版之外，额外给一个 3–5 行的精简版，措辞是"他可以直接转给上级"的口径：

```
【可转发版】
支付模块上线时间调整：8/15 → 8/29（+2 周）
原因：三方支付接口 7/20 交付（较约定晚 8 天），联调工作量超出预估。
影响：运营活动配置顺延，无对外承诺受影响。
处置：已确认新时间点，联调单独排期，8/22 前完成全链路验证。
```

跟用户说明白这是干什么用的：

> 「另外给你准备了一个可以直接转发的版本。你领导多半也得跟他上级说这事，你把这层替他准备好，他会记住你。」

## 五、几种具体场景的处理差异

### 5.1 项目延期

重点在新时间点的可信度。给一个新日期，必须同时给出"为什么这次这个日期是准的"，否则领导只会觉得还会再延。

### 5.2 目标未达成

区分两种情况：

- **目标定得不合理** → 不要在坏消息汇报里翻旧账。先说结果和补救，"目标设定"另找时机复盘
- **执行出了问题** → 说清楚是哪个环节，以及已经改了什么

给数字：达成了多少（68% 而不是"接近完成"）。

### 5.3 事故 / 线上问题

顺序严格：影响范围 → 是否已止血 → 根因 → 复发预防。

**"已止血"要放在很靠前的位置。** 领导看到坏消息的第一反应是"现在还在烧吗"。

### 5.4 自己的失误

- 承认具体的判断失误点，不做泛泛自我批评
- 立刻给补救动作和时间
- **不要过度道歉。** 一句就够，多了显得慌，也占用领导的注意力

### 5.5 资源被砍 / 关键人离职

这类不完全是"你的坏消息"，但需要向上暴露。

重点是把它转成**决策请求**：说清楚砍了资源之后哪些事做不了了，请领导选择砍哪个目标。不要默默扛下来然后年底解释为什么没做完。

## 六、写完后的自检

- [ ] 第一句话就说清了坏消息本身？
- [ ] 有准确的数字（多久、多少、到什么时候）？
- [ ] 说清了谁受影响、谁不受影响？
- [ ] 给了至少两个方案并标了推荐？
- [ ] 明确了需要领导做什么、什么时候之前？
- [ ] 没有点名甩锅？
- [ ] 没有过度自责？
- [ ] 没有用模糊词淡化？
- [ ] 给了可转发版本？

---

## 七、模拟评审在 M6 建议默认开启

坏消息是高风险场景，值得多花一轮。

模拟评审时的评审角色要特别设定为"**刚看到这个坏消息、情绪不太好的领导**"，重点检查：

- 有没有让他觉得你在推责
- 有没有让他觉得你在瞒
- 他看完知不知道要干什么
- 他能不能直接拿去跟他上级说
